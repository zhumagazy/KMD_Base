# KMD Base — база знаний и тестирование

Внутренняя платформа компании: сотрудники изучают курсы, кандидаты и сотрудники сдают тесты,
администратор управляет контентом, доступами и результатами.

**Стек:** Python 3.12 · Django 5.2 · PostgreSQL (или SQLite локально) · серверный рендеринг без сборки фронтенда.
Такой стек разворачивается на любом хостинге: Render, Railway, PythonAnywhere, VPS, Docker.

## Роли

| Роль | Что может |
|---|---|
| **Администратор** | Группы курсов, курсы и материалы (статьи в Markdown, видео YouTube/Vimeo, файлы, ссылки); пользователи (сотрудники и кандидаты); доступы к группам/курсам с необязательным сроком; тесты, вопросы и разовые доступы к ним; результаты, ручная проверка развёрнутых ответов, экспорт в CSV. |
| **Сотрудник** | Видит только доступные ему курсы и группы, отмечает изученные материалы, проходит назначенные тесты и видит список сданных. Кандидат — это сотрудник с отметкой «Кандидат». |

## Тесты

- Типы вопросов: один верный ответ, несколько верных, развёрнутый ответ (проверяет администратор).
- Настройки: лимит времени, проходной балл, случайная выборка N вопросов, перемешивание вопросов и вариантов,
  «только после изучения курса».
- **Результат по умолчанию скрыт от пользователя** — включается флагом «Показывать результат пользователю»
  (и отдельно — «Показывать правильные ответы»).
- Доступ к тесту выдаётся **разово**: число попыток (по умолчанию 1) и необязательное окно «с — до».
  Можно добавить попытку, изменить окно или отозвать доступ.
- Таймер работает на сервере: по истечении времени попытка закрывается автоматически, ответы
  сохраняются по ходу прохождения.

## Загрузка курсов из папки

Курсы можно не набирать вручную, а положить файлы в папку `content/` в корне проекта.
При каждом запуске сервера (`start.sh`) они загружаются на сайт автоматически.
Вручную: `python manage.py import_content` (или `import_content путь/к/папке --dry-run` для проверки).

Пример — папка [`content_example/`](content_example):

```
content/
  01 Адаптация/                    ← группа курсов
    описание.txt                   ← описание группы (необязательно)
    01 Знакомство с компанией/     ← курс
      описание.txt                 ← описание курса
      01 О компании.docx           ← материалы
      02 Приветствие директора.url ← ярлык на YouTube → встроенное видео
      03 Регламент.pdf             ← PDF открывается прямо на странице
      тест.txt                     ← тест курса
  Отдельный курс/                  ← папка только с файлами = курс без группы
  Тесты/                           ← тесты без курса (например, для кандидатов)
    Входной тест.txt
```

- **Порядок** задаётся числом в начале имени (`01 `, `02 `) — в название оно не попадает.
- **Форматы материалов:** `.docx` (превращается в статью вместе с картинками и таблицами), `.md`, `.txt`,
  `.html` — статьи; `.url` — ссылки/видео; `.mp4` — видео с плеером; `.pdf` — встроенный просмотр;
  всё остальное (`.pptx`, `.xlsx`, `.doc`…) — файл для скачивания. Старый `.doc` лучше пересохранить в `.docx`.
- **Повторная загрузка** обновляет только изменившиеся файлы. Если материал отредактирован на сайте,
  а файл в папке не менялся, правки на сайте сохраняются.
- Доступы к курсам после загрузки выдаёт администратор на сайте.

### Формат теста (`тест.txt`)

```
# Тест: охрана труда
Время: 20
Проходной балл: 70
Показывать результат: нет

? Что нужно надеть перед работой?
+ Перчатки
+ Респиратор
- Галстук
Пояснение: см. материал «СИЗ»

? Можно ли смешивать средства?
- Да
+ Нет

? Опишите действия при попадании средства на кожу.
Баллы: 3
```

`?` — вопрос, `+` — верный вариант, `-` — неверный. Несколько `+` — вопрос с несколькими ответами,
без вариантов — развёрнутый ответ (его проверяет администратор). Другие настройки: `Вопросов в попытке: 10`,
`Перемешивать: да`, `Показывать ответы: да`, `После курса: да`.
Тест, по которому уже есть попытки, при повторной загрузке не изменяется — чтобы не испортить результаты.

> **Важно:** если курсы и тесты (с правильными ответами!) хранятся в репозитории, репозиторий должен быть
> **приватным**: GitHub → Settings → General → Danger Zone → Change visibility → Private.

## Цвета бренда

Сайт kazmeddez.kz был недоступен из среды разработки, поэтому цвета в `static/css/brand.css` —
временные. Подставьте HEX-коды из брендбука в этот файл — весь интерфейс перекрасится.
Остальной дизайн следует Apple Human Interface Guidelines: системный шрифт SF Pro, крупные заголовки,
сгруппированные списки, переключатели, светлая и тёмная тема, таб-бар на мобильных.

## Локальный запуск

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python manage.py migrate
python manage.py import_content content_example   # пример курсов из папки
python manage.py seed_demo        # демо-данные: admin/admin12345, employee/employee12345, candidate/candidate12345
python manage.py runserver
```

Откройте http://127.0.0.1:8000. Без демо-данных создайте администратора: `python manage.py createsuperuser`.

Тесты: `python manage.py test tests`

## Деплой

### Render.com (проще всего)
1. New → **Blueprint** → выберите репозиторий — `render.yaml` создаст сайт, PostgreSQL и диск для файлов.
2. Задайте `ADMIN_PASSWORD`, после деплоя войдите как `admin`.
3. В Settings → Custom Domain подключите свой домен и добавьте его в `ALLOWED_HOSTS` и `CSRF_TRUSTED_ORIGINS`.

### Хостинг в Казахстане

Закон РК «О персональных данных» требует хранить базы с персональными данными граждан РК на серверах
в Казахстане. Для боевого запуска подойдёт VPS у казахстанского провайдера (PS.kz, Hoster.kz и др.)
с Docker — инструкция ниже. Render удобен для пробного запуска.

### Docker / VPS
```bash
docker build -t kmd-base .
docker run -p 8000:8000 --env-file .env -v kmd-media:/var/data/media kmd-base
```
Переменные окружения описаны в `.env.example`. Перед контейнером поставьте nginx/Caddy с HTTPS.

## Структура

```
config/      настройки, маршруты (manage_urls.py — раздел администратора /manage/)
accounts/    пользователи, роли, управление пользователями и доступами
learning/    группы, курсы, материалы, доступы, прогресс
exams/       тесты, вопросы, разовые доступы, попытки, проверка
templates/   HTML-шаблоны (employee/ — сотрудник, manage/ — администратор)
static/css/  brand.css — цвета бренда, app.css — интерфейс
```

Резервный интерфейс Django Admin доступен по адресу `/django-admin/`.
